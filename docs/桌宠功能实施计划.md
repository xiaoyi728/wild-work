## 1. 目标

给 wild-work 增加一只桌宠，形象为项目所有者提供的平涂风仓鼠（**风格锁定，不得像素化、不得改画风**）：

1. **阶段一（先做）**：Web 管理面板内的角落桌宠，随真实运行状态变换动画与眼神、腮红。
2. **阶段二（后做）**：桌面常驻桌宠（透明置顶、点击穿透、拖拽、随桌面启动），**复用同一份美术资产与同一套状态语义**。

### 2.1 P9 硬约束（不可协商项）

桌宠是**附加观感层**，任何情况下都不得改变既有行为。具体化为可判定的规则：

**后端**
1. **只增不改**：允许新增字段/端点/结构体字段；**禁止**修改任何既有函数签名、既有 JSON 字段名与语义、既有路由的行为。
2. `/api/pulse` 只读两个 `atomic` 计数器，**不查 ledger、不扫文件、不碰 pool**；R17「ledger 仅在 UI 请求时按月扫描」的设计不得因此功能而被高频轮询绕过或破坏。
3. 流量计数埋点**只加不改**：在 `chatCompletions` 已选定账号之后追加两行，不得调整该函数任何既有分支、错误分类、冷却、粘性路由逻辑（不变量 §6.11、§6.8）。
4. `Runtime` 新增字段一律**零值安全**（`Alias bool` 默认 false、`traffic atomic.Int64` 默认 0），旧装配代码不赋值即行为不变。
5. **不改 `config.Default()` / `config.example.json`**：桌宠开关只存浏览器 localStorage，不进 `config.json`（既避开 §6.7 同步义务的风险，也让未装桌宠的旧配置文件原样可用）。
6. 状态文件（`data/state-*.json`）字段口径零改动，本功能不新增落盘内容。
7. **日志零 token** 不变量（§6.2）继续成立：桌宠相关代码不得输出任何凭证。

**前端**
8. 桌宠 DOM 由 `pet.js` 自行 `appendChild` 到 `<body>`，`position: fixed`，**不进入 `.container` 栅格**，不改动任何既有元素的选择器、层级或样式。
   左右双边吸附（§7.7）同样只改自身的 `left/right/bottom`，**不得引入或消除页面滚动条**（吸附后 `scrollWidth == clientWidth` 必须仍成立）。
9. 新增样式独立成 `pet.css`，**不修改 `style.css` / `anim.css` 的既有规则**。
10. `app.js` 对桌宠的调用点**全部判空**（`if (window.Pet)` / `typeof Pet !== "undefined"`）：删掉 `pet.js` 后页面必须照常工作。
11. 既有交互（签到/刷新/停用/删除/改名/登录/费率/用量/设置）的行为与请求序列不得变化；桌宠只**观察** `/api/state` 结果，不参与渲染决策。
12. 关闭桌宠开关后**必须零轮询**（清 interval + cancel rAF），网络面板不得再出现 `/api/pulse`。

## 3. 调研结论

### 3.1 Codex Pet 包格式（动画语义的来源，值得照搬其契约）

- 一个宠物 = 一个文件夹：`pet.json` + `spritesheet.{webp,png}`
- **v1**：1536×1872，**8 列 × 9 行**；**v2**：1536×2288，**8 列 × 11 行**；单元格恒为 **192×208**
- `pet.json` 字段：`id` / `displayName` / `description` / `spriteVersionNumber`（须为 `2`）/ `spritesheetPath` / `glow{primary, accent}`
- **核心契约：行 = 状态，列 = 该状态的第 N 帧**；宿主把 agent 真实活动映射到行号，运行时循环播放该行
- 状态行示例：idle / running-right / running-left / waving / jumping / failed / waiting / review
- `glow` 用于宿主给宠物描一圈与状态呼应的辉光
- 分发：`npx petdex install <slug>` → `~/.petdex/pets/<slug>/`；`petdex.dev/api/manifest` 是稳定公共接口
- 桌面端实现：原生 App（Zig + 进程内 hook server `127.0.0.1:7777`），**刻意不含 WebView / Node 旁路**

> 借鉴点：**状态→行的映射契约**。不借鉴：精灵表 atlas（与 P5「不平涂化」冲突）。

### 3.2 clawd-on-desk（阶段二宿主）

- 仓库 `rullerzhou-afk/clawd-on-desk`，JavaScript/**Electron**，6.2k★，**AGPL-3.0**
- 平台：Windows 11 / macOS / Ubuntu-Linux
- **已内建集成我们聚合的全部上游**：WorkBuddy、Qoder、QoderWork、千问办公（QwenWork）、TraeCode（Trae CN）——通过各 agent 自己的 hooks 文件
- 现成能力：透明置顶窗、**点击穿透（仅身体可交互）**、拖拽（Pointer Capture）、位置记忆、边缘 Mini 模式、托盘、开机自启、DND、音效、多会话聚合、Dashboard/HUD、权限气泡、移动端 PWA 镜像
- **眼神跟随是内建功能**：`eyeTracking.enabled: true` 时，被列入 `eyeTracking.states` 的状态资源**必须是 SVG**，且该 SVG 需含 `#eyes-js` 图层组 → 宠物自动跟随鼠标光标，带身体倾斜与影子拉伸
- 动画状态 12 个：idle / thinking / typing / building / subagent groove / juggling / error / happy / notification / sweeping / carrying / sleeping
- 主题格式：

  ```text
  hamster/
    theme.json                  ← 必需：name / author / states 文件映射 / eyeTracking 开关
    assets/
      idle-follow.svg           ← eyeTracking.states 里的状态必须 SVG + #eyes-js
      working.svg  happy.svg  error.svg  sleeping.svg  ...
    sounds/                     ← 可选
  ```
  单资源格式可为 SVG / GIF / APNG / WebP / PNG / JPG；「Advanced: Full SVG + CSS Animations」档无限制
- 用户主题目录：**Windows `%APPDATA%/clawd-on-desk/themes/hamster/`**；macOS `~/Library/Application Support/clawd-on-desk/themes/hamster/`；Linux `~/.config/clawd-on-desk/themes/hamster/`
- 脚手架与校验：`node scripts/create-theme.js hamster`、`node scripts/validate-theme.js <dir>`
- 支持导入 Codex Pet zip 包并适配成托管主题

**外部状态接入契约（Custom HTTP Agent，v1 只读状态、不参与权限决策）**：

1. 在 clawd `Settings → Agents` 注册本应用为 custom agent，得到 `agent_id` 与 state endpoint
2. **不得硬编码端口**：clawd 只绑 `127.0.0.1`，取 `23333–23337` 第一个可用端口，运行期写 `~/.clawd/runtime.json`：

   ```json
   { "app": "clawd-on-desk", "port": 23334 }
   ```
   每次发送前读该文件并校验 `app === "clawd-on-desk"`；文件缺失/畸形/连接被拒 → **视为 clawd 离线，静默跳过，绝不阻塞主业务**
3. `POST http://127.0.0.1:<port>/state`，`Content-Type: application/json`：

   ```json
   { "agent_id": "custom-xxx", "session_id": "wild-work", "state": "working", "event": "PreToolUse" }
   ```
4. 该端点**明确拒绝浏览器发起的请求**（要求字面 loopback 权威、**省略 `Origin`**、恰好一个 `Host` 与一个 `application/json` 的 `Content-Type`）→ **事件源必须是 Go daemon，不能是网页 JS**。Go 的 `net/http` 天然满足这些条件。

**许可证边界（重要）**：clawd 是 AGPL-3.0。本项目**不 fork、不复制其任何源码**，只：① 产出主题目录（SVG + JSON，属数据资产）；② 通过 localhost HTTP 向其公开契约发送状态字符串。二者均为独立程序间通信，不产生衍生作品关系，不触发 AGPL 传染。clawd 本体由项目所有者自行下载安装。

```
文件：项目所有者提供，1024×1024
alpha：全 255（无透明通道，背景 #2e3031 为实心底）
色块（可干净分离）：
  背景   #2e3031
  毛色   #e9c28d（浅驼）
  肚皮   #fae7cb（奶油白）
  眼睛   #000000（纯黑竖直胶囊，无眼白/无高光/无瞳孔）
  腮红   #efab78 / #eda979（橙色椭圆，左右各一）
  墨镜   #303233（推在头顶；与背景色仅差 2–3 阶，需靠空间位置而非色键区分）
主体 bbox：x 0–872, y 136–1020 → 左侧与底部出血出框（肚皮被裁）
```

**由数据得出的两个限制**：

1. 眼睛是纯黑胶囊 → **无法做"瞳孔转动"式眼神**。解决方案（符合 P5 不改风格）：**把整颗黑胶囊当瞳孔**，做平移 + 微旋转 + 纵向压缩（眨眼），风格零损失。故不需要眼白，也不需要为此生图。
2. 原图被裁切 → 项目所有者确认**不需要未裁切版**（P10），桌宠按现有构图作为角落近景使用。

### 4.1 实际拆层结果（已落地，零新增生图）

拆层脚本一次性从原图产出 5 张**同画布同坐标**的 320×320 图层（合计 63 KB，全部 `go:embed` 进二进制）：

| 图层 | 实测质心（归一化，即 CSS `transform-origin`） | 像素数 |
|---|---|---|
| `body.png`（已挖除眼/腮红并补色，**镜框完整保留**） | — | 主体 637342 |
| `eye-l.png` | 33.03% / 43.26% | 7750 |
| `eye-r.png` | 58.62% / 52.60% | 7703 |
| `blush-l.png` | 20.07% / 51.48% | 10021 |
| `blush-r.png` | 64.61% / 67.27% | 10116 |

拆层过程中踩到并已在脚本里固化成判据的三个坑（复用此法换形象时必须照做）：

1. **背景与墨镜几乎同色**（`#2e3031` vs `#303233`，仅差 (2,2,2)）→ 全局色键会把镜框一起抠掉。
   改用**从四条边洪泛**求背景连通域，被毛色包围的镜框天然不受影响。
2. **镜框描边是纯黑**，与眼珠同色 → 单靠 `r<20` 会把 456×237 的空心镜框误判成眼睛并把它从 body 上挖掉。
   加形状判据排除：**必须「高 > 宽」且「填充率 > 0.4」**（真眼珠 86×145 填充率 0.62，镜框填充率仅 0.10）。
3. **抗锯齿环**：`r<20` 只抓到眼珠核心，边缘深棕过渡带残留会（a）在 body 上留脏痕、（b）污染补色。
   解法：挖洞半径膨胀到 **14px**；图层 alpha 用线性混合反解 `α = |c−base| / |stroke−base|`（`base` 取部件外围环带中位数）；
   body 空洞用 **Voronoi 最近邻原色填充**（绝不用邻域平均，平均必然带出脏色）。
   量化校验：补色区均色 `#e9c391` vs 真毛色 `#e9c38d`，**暗于 `#80` 的像素 0 个**。

## 6. 状态表（两宿主共用同一套语义）

| 状态 | 判据（数据源字段） | 动画表现 | 后端是否需新增 |
|---|---|---|---|
| `idle` 待机 | 默认态 | 呼吸起伏（scaleY ±2%）、随机眨眼、**眼神跟随鼠标**、偶发左顾右盼 | 否 |
| `working` 干活 | **`/api/pulse` 请求计数在增**（阶段一）；daemon 直推（阶段二）；积分 spend 流水作次级"吃到"反馈 | 墨镜滑到眼睛、双爪敲键盘、身体前倾、随请求节奏抖动 | **是**（§7.2） |
| `happy` 开心 | 出现新的 `last_checkin_ok=true`；或签到/刷新成功 toast | 眼睛变弯月、腮红变浓、蹦一下、小心心 | 否 |
| `hungry` 缺粮 | 存在账号 `credits < 阈值` | 撇嘴、眼神下看、肚皮轻微凹陷 | 否 |
| `urgent` 临期 | 任一账号 `expiring_credits > 0`（与顶栏临期口径同源，R18） | 举爪拍打、腮红褪成冷汗滴 | 否 |
| `error` 生病 | 任一账号 `cooling` 或 `err_count ≥ 3` | 眼睛变 X、身体变灰、冒黑线 | 否 |
| `stale` 待刷新 | 任一账号 `credits_stale` | 头顶转圈、眼神放空 | 否 |
| `asleep` 沉睡 | 请求静默 > 15 分钟；或页面 `document.hidden` | 闭眼、Zzz、呼吸幅度变大、耳朵下垂 | 否 |

**优先级聚合**：多条件同时成立时取最高优先级 —— `error > urgent > stale > working > happy > hungry > asleep > idle`（与 clawd「多会话取最高优先级态」一致）。

### 7.7 左右双边吸附（后补需求）

**动机**：原画的形体是从**左/下出框**的（身体被画布左缘与底缘切断）。贴右下角摆放时，出框边朝向屏幕内侧，
看起来像"从左边滑出来"，与画面重心矛盾。因此必须支持双边停靠，并让出框边始终贴住对应的窗口边。

| 停靠侧 | 类 | 镜像 | 出框边对齐 | 浮层展开方向 |
|---|---|---|---|---|
| 左 | `.dock-left` | 否（原图） | 左缘贴窗口左边 | 向右（`left:0`） |
| 右（默认） | `.dock-right` | **`scaleX(-1)`** | 右缘贴窗口右边 | 向左（`right:0`） |

- 拖拽期间自由跟手（写 `left/top`，清 `right/bottom`），**松手按宠物中心离哪条竖边近即时吸附**，纵向位置保留
- 镜像放在独立的 `.pet-art` 包裹层上，不占用 `.pet-stage` 的呼吸动画 `transform`（否则互相覆盖）
- 镜像侧的眼神位移取反：`flip = side === "right" ? -1 : 1`，否则眼睛会盯着屏幕外侧
- 窗口 `resize` 时重新吸附并钳制 `bottom`；`{side, bottom}` 存 localStorage
- 浮层「换到左边/换到右边」按钮可手动切边

**实现过程中发现并修掉的两个真缺陷**：

1. **拖拽残留的行内 `top` 会劫持吸附结果** —— CSS 中 `top`/`bottom`/`height` 同时确定时 `top` 胜出、`bottom` 被忽略。
   `dock()` 原先只设 `left/right/bottom` 不清 `top`，导致吸附后垂直位置仍由拖拽残留值决定。
   修法：`dock()` 内 `el.style.top = ""`。
2. **`left`/`right` 的位置过渡不可靠** —— 停靠切换时一侧会从具体像素变成 `auto`，`auto` 无法插值；
   且隐藏标签页里 CSS transition 会被冻结在中间帧（实测 `computedLeft` 卡在 `108px` 而 inline 是 `0px`）。
   修法：去掉位置过渡，吸附改为即时（与 clawd 的 mini-mode 吸附一致）。

**实测**（`evaluate_script` 读几何，非截图）：左停 `leftEdge=0` 且 `mirrored=false`；
右停 `mirrored=true` 且右缘贴住可用视口边（`innerWidth - r.right = 15` 即竖滚动条宽，属正常参照系差异）；
拖到上半区松手 → `inlineTop` 已清空、`computedBottom=639px` 生效 ✓。

### 8.2 推送器设计

```
每 1s 采样：
  traffic 计数增量 → working / 静默计时 → asleep
  pool 状态：cooling / err_count / credits / expiring_credits / stale
  签到结果：复用既有 NotifyCheckin 通路
→ 按 §6 优先级算出目标态
→ 仅在「状态发生变化」时 POST（去重，避免每秒打 clawd）
→ 状态字符串白名单：idle working happy error notification sleeping
```

- 端口发现：每次发送前读 `~/.clawd/runtime.json`（Windows 为 `%USERPROFILE%\.clawd\runtime.json`），校验 `app === "clawd-on-desk"`，**不硬编码 23333**
- 失败策略：文件缺失 / 端口拒连 / 非 2xx → **静默降级**，记一行日志（**零 token，遵守 §6.2**），不影响任何业务路径；连续失败则退避到 30s 重试
- 请求形态：`net/http` 直连字面 `http://127.0.0.1:<port>/state`，`Content-Type: application/json`，**不带 `Origin`**（Go 默认不加）
- `session_id` 固定 `"wild-work"`；`agent_id` 来自配置

### 8.3 配置（遵守 §6.7 同步义务）

```json
"pet": {
  "enabled": false,
  "agent_id": "",
  "push_states": ["working", "happy", "error", "sleeping"]
}
```

- `config.Default()` 与 **`config.example.json` 必须同步新增**（不变量 §6.7）
- **默认 `enabled: false`**：未安装 clawd 的机器不应产生任何无谓的 runtime.json 读取与重试
