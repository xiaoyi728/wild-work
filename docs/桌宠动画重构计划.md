## 1. 缘起与参考来源

项目所有者要求参考 **`sheng-yh/Reproduce-grok-bot-icon`** 的设计重构桌宠动画，并**保持当前桌宠形象不变**。

该仓库是 xAI `x.ai/bot` 上 Grok 机器人图标的复刻（HTML/SVG，201KB，`src/shapes-module.js` + `src/grokbot-module.js`）。
实测其动画内核有四件事：

1. **运动是物理而非补间**：每个动画属性是一个弹簧对象 `{ x, v, t }`，用临界阻尼弹簧积分
   `v += (−2ζω·v − ω²(x − target))·dt`，`x += v·dt`，固定步长 `dt = 1/120 s`，并带
   `Number.isFinite` 兜底（数值炸掉时直接把 `x` 归到 `target`、`v` 归零）。
2. **一个状态 ≠ 一副姿势**：三张表 `f`（state → 候选表情索引）、`A`（state → `[min,max]` 随机切换间隔 ms）、
   `m`（state → 停留时长）驱动，同一状态下在若干副表情之间**随机轮换**，这是"活"的主要来源。
3. **表情是数据**：25 种眼型各存为约 50 点的点环，`lerpRing` 逐点插值 → 表情之间"融化"过渡；
   17 种头廓同理（光线投射生成 96 点可插值环 + `top/bottom/spanAt(y)` 查找表供每帧裁剪眼睛）。
4. **动画期 React 从不重渲染**：rAF 循环内直接经 ref 写 SVG 属性；配色走 CSS 变量（`--fg`/`--bg`）继承宿主主题。

该仓库 LICENSE 为 **保留所有权利**，并自述"美术与动画引擎是对 xAI Grok 机器人图标的复刻，仅供学习参考，
请勿将美术资源用于商业分发"。

## 3. 现状（改动基线，实测）

- `cmd/wild-work/web/pet.js` 370 行、`pet.css` 112 行、`web/pet/*.png` 5 张共约 63KB。
- 输出通道：`--ex/--ey`（眼珠位移=眼神）、`--eb`（眼珠纵向压扁=眨眼）、`--bo/--bs`（腮红不透明度/缩放）、
  `--tilt`（整体倾斜），由 `frame()` 每帧直接写 `el.style`。

- 数据：`/api/pulse`（3s，`{requests, last_request_ms}`，埋点在 `handler.go` 选定账号即将打上游处，
  三种协议经 `internal/gateway` in-process 汇聚故单点全覆盖）+ `/api/state`（30s，由 app.js `Pet.sync()` 推进来）。
- 已有良性设计保持不动：`document.hidden` 暂停 rAF 与轮询、`petGet()` 自带容错不复用全局 `api()`、
  4 个 `if (window.Pet)` 判空触点、`Pet.init()` 独立于 `init()` 启动。

已知瑕疵（本次一并处理，见 P3 阶段）：`.pet` 的 `z-index: 120` 高于弹层遮罩 `.overlay` 的 100，
打开设置/费率弹层时桌宠浮在遮罩之上。

## 5. 目标架构

### 5.1 分层（越往下越稳定，语义层零改动）

```
数据层   /api/state 账号快照 + /api/pulse 计数        ← 契约不变
   ↓
语义层   resolve() 8 态优先级判定                     ← 一字不动（Q2）
   ↓
表现层   MOTIFS[state] 随机选 motif + 随机停留          ← 新增（Q3）
   ↓
内核     弹簧对象 ×N：target 由 motif 给，x 每帧积分    ← 新增（Q1）
   ↓
输出     el.style.setProperty('--ex'|'--eb'|...)       ← 现有通道 + 2 个新通道
   ↓
消费     pet.css（transform/opacity/clip-path）        ← 只碰合成层，不动布局
```

### 5.2 弹簧内核

```js
// mk(v) → {x:v, v:0, t:v}
// step(s, omega, zeta, dt)：v += (−2ζω·v − ω²(x − t))·dt；x += v·dt
// 每帧把真实 delta 累加，按固定 1/120s 多次 sub-step 积分 → 掉帧不失稳
// Number.isFinite 兜底：炸值时 x=t、v=0
```

各通道用不同 `(ω, ζ)`：眼神跟随要"跟得上但不飘"（高 ω、临界阻尼），
身体浮动要"有重量"（低 ω、略欠阻尼），眨眼/挤压是**一次性时间脚本**（走缓动函数而非弹簧，避免回弹把眨眼变成抖眼）。

### 5.3 新增输出通道

| 变量 | 含义 | 消费者 |
|---|---|---|
| `--bob` | 身体上下浮动（px） | `.pet-art { translateY(var(--bob)) }` |
| `--squash` | 挤压拉伸（x/y 反向） | `.pet-art { scale(var(--sq-x), var(--squash)) }` |
| `--eye-clip` | 眼珠遮罩形状（弯月眼程度 0~1） | `.pet-eye { clip-path: ... }`（Q5，可关） |

### 5.4 数据环（若 §12 拍板要）

独立 SVG 层，位于原画**外圈**，不覆盖身体：

- 进度环：今日签到完成度（`checked / total`，来自 `/api/state`）
- 轨道点：活跃（非 disabled、非 cooling）账号数，每号一点
- 配色：`--ok` / `--warn` / `--danger`，随三套主题自动变
- 约束：`pointer-events: none` 不变、只 `transform`/`opacity`/`stroke-dashoffset`、可整体关

## 6. 状态 × motif 设计表

motif = 一组「在 D ms 内把各通道 target 打到哪里」的脚本；同态内按 `[min,max]` 随机间隔轮换（Q3）。

| 状态 | motif 候选 | 随机间隔 | 备注 |
|---|---|---|---|
| `idle` | 呼吸浮动 / 歪头 8° / 单眼眨 / 眼神游走 | 6~16s | 游走时视线随机停在画面内某点 1~2s，不再一直追鼠标 |
| `working` | 小幅点头节拍（随 `pulse.requests` 增量踩点） / 眼神定向"看屏幕里侧" | 3~7s | 增量驱动沿用 P7，不改判据 |
| `urgent` | 腮红加深 + 头微偏看向前方 / 快速双眨 / 视线在临期账号方向徘徊 | 4~9s | 判据与文案完全不动 |
| `error` | 缩一下（squash） / 腮红转 `--danger` 调 / 高频小幅颤 | 2~5s | 幅度受控，不做恐怖谷式抽搐 |
| `stale` | 缓慢左右张望 / 半闭眼 | 5~10s | |
| `happy` | backOut 弹起 + 弯月眼（若启用 Q5）+ 可选迸发（默认关） | 一次性 1.2s | 触发条件不变：`sync()` 比对快照得出（自动签到也能触发） |
| `hungry` | 低头看下方 / 慢呼吸 / 偶发抬头 | 5~10s | |
| `asleep` | 极慢呼吸（幅度加倍） / 偶发眼皮抽动 / 头缓垂 | 8~20s | 15 分钟静默判据不变 |

## 11. 验收标准

1. 眼睛跟随鼠标：急停后**有过冲再收敛**（弹簧特征），而非到位即停；收敛时间 < 400ms。
2. 状态切换：`idle → error` 之间参数连续，无跳变帧（逐帧采样 `--tilt` 差分无 >3° 的单帧突跳）。
3. 同处 `idle` 连续观察 60s，能看到 ≥3 种不同微动作，且间隔不规则（非固定周期）。
4. `asleep` 呼吸周期 ≥ 4s，`working` 点头与实际请求增量相关。
5. `prefers-reduced-motion: reduce` 下：motif 与粒子全停，仅保留状态配色与静态姿势。
6. 不可见标签页 0 CPU；可见静置时 rAF 内单帧 JS 耗时 < 1.5ms。
7. §8 七条硬约束逐条通过；§9 门禁全绿。
8. 面板既有功能零回归：登录弹层、费率弹层内多标签、账号卡积分计数动画、Paper 主题。
9. `dist/wild-work.exe` 与 `dist/wild-work-linux` 已重建，并按 AGENTS.md L4 的**本版独有标记**
   （数 `chatglm`/`admin_password` 之类，**不要**数版本号字节——`crypto/x509/pkix` 的 DN OID 会污染）核对。

### 13.2 实测中挖出并修掉的两个真实缺陷

1. **累加器没有下限**：`dt = min(0.1, (ts − lastTs)/1000)` 在 ts 倒退时得到负值，`acc` 被拖成 −60，
   `while (acc >= 1/120)` 从此不再执行 → **弹簧整体停摆**（表现是「宠物突然冻住」，`--bob` 恒为 0）。
   修法：`Math.max(0, ...)` 钳下限，并对 motif 局部时间同样取 `Math.max(0, ts − motifAt)`。
   测试环境里手工注入时间才能撞上，但真实浏览器对同一帧给过更早/相同 ts 的情况确实存在，属必修。
2. **一次性动作与帧循环不同域**：`pushShot` 用 `performance.now()` 取 `t0`，而 rAF 回调的 `ts` 是**帧起始时刻**、
   略早于回调内的 `performance.now()` → 动作会晚 1~2 帧才起效。修法：`t0` 改取最近一帧的 `ts`（`lastTs || performance.now()`），
   粒子同一处理。副作用：注入虚拟时间的测试里，若虚拟时钟落后真实时钟 >粒子寿命，粒子会被判过期——
   **这是测试假象**，生产单调 rAF 时钟下不会发生（复测时在全新页面驱动即恢复正常）。

### 13.3 观感待用户确认项

`ww-pet-crescent` / `ww-pet-burst` 两个默认 `off` 的开关需要用户亲眼看一次再定默认值：
`happy` 状态下（签到成功或积分上涨）弯月眼会把眼珠裁成越来越扁的椭圆镜头，受 PNG 圆形瞳孔限制，
是「眯眼」而非真正的 ∩ 形笑眼——不满意就保持默认关闭，代码留着不影响现状。

### 14.2 数据环：先量角度再画

`body.png` 在 art 坐标系里把 **145°~272°（左下出框那侧）占死**，逐角度实测 alpha 后可用的扇区是

绝不压到原画；环画在 `.pet-art` 内部 → 靠右停靠时随整幅画一起镜像，不必为两侧写两套角度。

- 进度 = 今日已签到 / 可用账号数（`disabled` 不计入分母），用 `pathLength="100"` 归一化后
  只写 `stroke-dashoffset`；日期口径按 **UTC+8 墙钟**取 `last_checkin_at` 前 10 位（不变量 18 同源），
  不用浏览器本地时区。
- 轨道点 = 活跃账号（非 `disabled`、非 `cooling`、`err_count<3`）每号一点，沿同一弧均分，**16 个封顶**。
- 色调：`error` → `--danger`，全签 → `--ok`，其余 → `--warn`，全部取主题变量，三套皮肤自动跟随。
